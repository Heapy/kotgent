# Пре-план — ссылки в терминале: `linkHandler`, голые URL и `file:line` в IDE

**Статус:** находка + рассуждение. Не план. Следующий шаг — `/planning:make` по этому файлу.

## Находка

Всё нужное есть в вендоренной 6.0.0 (номера строк — из `git show 6.0.0:typings/xterm.d.ts`):

| Что | Где |
|---|---|
| `registerLinkProvider(ILinkProvider): IDisposable` | `typings/xterm.d.ts:1102` |
| Опция `linkHandler?: ILinkHandler \| null` | `typings/xterm.d.ts:163` |
| `ILinkHandler.allowNonHttpProtocols` | `typings/xterm.d.ts:1387` |
| OSC 8 разбирается ВСЕГДА — `OscLinkProvider` регистрируется в конструкторе | `src/browser/CoreBrowserTerminal.ts:160` |
| Эталон провайдера по регулярке (в т. ч. консервативная regex для URL) | `addons/addon-web-links/src/WebLinkProvider.ts`, `WebLinksAddon.ts:21` |

**И побочная находка, которая, возможно, важнее основной.** В наших исходниках нет ни `linkHandler`, ни
`registerLinkProvider` (проверено grep-ом по `app.js`, `lib/`, `components/`). А документация опции
говорит прямо: *«Links will use the `confirm` browser API with a strongly worded warning if no link
handler is set»*. То есть сегодня OSC 8 гиперссылка от агента — а их эмитят и `claude`, и инструменты
внутри — даёт пользователю пугающий системный `confirm`. Мы это не задумывали; это просто дефолт, до
которого не дошли руки.

## Почему это важно

Три разные вещи, у которых разная цена и разная польза, — и их стоит разделить сразу, потому что
соблазн сделать «фичу про ссылки» одним куском.

1. **`linkHandler` (баг-фикс).** Агент уже умеет присылать OSC 8, а мы отвечаем страшным диалогом.
   Правильное поведение — открывать `http(s)` в новой вкладке с обнулённым `opener` (образец —
   `WebLinksAddon.ts:24-36`), остальное игнорировать. Маленько, самостоятельно, ничего не требует.
2. **Голые URL (недостающее удобство).** Агенты постоянно печатают URL — доки, PR, issue. Сейчас они не
   кликабельны, и на телефоне их не выделить (drag перехвачен свайп-бриджем,
   `components/TerminalPane.js:93`, `:539`).
3. **`path:line` → IDE (собственно фича).** Вывод агента полон `src/foo/Bar.kt:42`. Мы знаем cwd сессии
   на клиенте (`lib/sessions.js:56`, `components/Sidebar.js:74`), значит относительный путь резолвится
   в абсолютный без единого запроса к демону.

Пункты 1 и 2 — это «привести терминал к тому, чем он и так должен быть». Пункт 3 — новая функция.

## Варианты для пункта 3 (что делает клик)

**A. URL-схема редактора (рекомендую).**
`vscode://file/<abs>:<line>:<col>`, для JetBrains — `jetbrains://idea/navigate/reference?project=<name>&path=<path>`.
*Плюс:* никакого нового API на демоне, никакой новой поверхности выполнения. Открытие внешней схемы —
решение браузера и пользователя.
*Минус:* JetBrains-схема требует ИМЕНИ проекта, которого у нас нет (cwd ≠ имя проекта). Возможно,
работоспособна только форма VS Code; проверять в field-check.

**B. Копировать `path:line` в буфер обмена.**
*Плюс:* тривиально, безопасно, работает везде. *Минус:* пользы мало — это то же самое, что выделить
мышью, только без выделения.

**C. Эндпоинт на демоне, запускающий `idea --line N <file>`.**
**Нет.** Это исполнение произвольного пути из потока, который пишет не наш код. Записать как
отвергнутое, чтобы не всплыло снова.

**Рекомендация: A, деградирующая в B**, если схема не настроена.

## Настройка

Схема редактора — **device-local preference**, ровно как `terminalUnicode`: она про то, что установлено
на ЭТОЙ машине, а не про сессию и не про демон. Механизм готов: `lib/prefs.js:16-18` (ключи
localStorage), `:30` (`sanitizePrefs`), `:87` (`persistTerminalUnicode` как образец записи).

**По умолчанию — выключено.** Открытие внешнего приложения по клику в терминале — не то, что должно
случаться неожиданно; и на телефоне, и в чужом браузере это будет странно. Пункты 1 и 2 при этом
работают всегда: они ничего наружу не запускают.

## Field-checks перед планом

1. **Работает ли `jetbrains://idea/navigate/reference` без имени проекта** — и что делает Chrome/Safari
   с незарегистрированной схемой (тихо ничего или диалог). Это определяет, живёт ли JetBrains-вариант
   вообще. Пользователь работает в IDEA, так что это гейт для полезности, а не деталь.
2. **Тап по ссылке на телефоне.** Свайп-бридж делает `preventDefault()` на claimed move, чем гасит весь
   compatibility-mouse-burst; тап без движения claimed не считается и должен пройти, но это надо
   увидеть, а не вывести. Если не проходит — на телефоне остаются только пункты 1 и 2, и то частично.
3. **Стоимость `provideLinks`.** Он вызывается на строку при наведении; под агентским TUI, который
   перерисовывается непрерывно, дешевизна регулярки не роскошь. Померить на живой сессии.
4. **Что реально печатают наши три агента.** Собрать образцы: `src/a/B.kt:42`, `a/B.kt:42:7`,
   `./a/B.kt`, абсолютные пути, пути в кавычках, пути с двоеточием внутри диагностики компилятора.
   Регулярка должна строиться по образцам, а не по воображению.

## Риски

- **Ложные срабатывания.** `1.2.3:4` в логе, `http://host:8080` (двоеточие + цифры) — подчёркивание
  всего подряд раздражает сильнее, чем отсутствие ссылок. Начинать с узкой регулярки, требующей
  расширения файла и/или `/` в пути.
- **Ссылки — это состояние поверх непрерывно меняющегося буфера.** Под агентским TUI строка под курсором
  мыши переписывается по нескольку раз в секунду; провайдер обязан быть чистой функцией строки, без
  кэша, живущего дольше кадра.
- **cwd может устареть.** Клиент берёт cwd из строки сессии; агент внутри пейна мог сделать `cd`.
  Резолв даст неверный абсолютный путь. Записать как ограничение — альтернатива (спрашивать у tmux
  `#{pane_current_path}`) означает запрос к демону на каждое наведение мыши, что несоразмерно.
